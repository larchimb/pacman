# Pac-Man

## Description

A remake of the arcade classic **Pac-Man**, written in Python 3.10+.

Pac-Man moves through mazes generated by the A-Maze-ing package we were given.
To clear a level, he must eat every pacgum before the timer runs out, while four
ghosts with different behaviours hunt him. When he eats a super-pacgum, the ghosts
become edible for a few seconds. The game has 10 levels, and each one is bigger
than the previous one. At the end of the game (win or lose), the player can enter
a name and save the score in a top 10 highscore table.

Main features:

- 10 procedurally generated levels (level 1 uses a fixed seed, the others are random).
- 4 ghosts, each with its own AI (chase, ambush, random, shy).
- HUD with score, lives, level and time left.
- Main menu, instructions screen, pause menu, game over / victory screen.
- Persistent top 10 highscores, with the last player's score highlighted.
- Cheat mode for testing and for the defense.
- Fully configurable through a JSON file (with `#` comments).
- Packaged with PyInstaller and published on Itch.io.

The graphics follow the **MLX rule** from the subject: we only use `pygame` functions
that have an equivalent in the MiniLibX (images, pixels, text, keyboard events).
There is no `pygame.draw`, no `pygame.transform`, no sound and no transparency.

## Instructions

### Requirements

- Python **3.10 or later**
- [`uv`](https://docs.astral.sh/uv/), recommended to install the dependencies
- The `mazegenerator-2.1.0-py3-none-any.whl` package, shipped in this repository

### Install and run

```bash
make install                   # uv sync: pygame, mazegenerator (.whl), dev tools
make run                       # same as: python3 pac-man.py config.json
make run ARG=my_config.json    # run with another config file
```

Without `uv`:

```bash
python3 -m pip install --user pygame mazegenerator-2.1.0-py3-none-any.whl
python3 pac-man.py config.json
```

## Configuration

The game takes exactly one argument: the path of a JSON config file. Lines (or the
end of a line) starting with `#` are comments and are ignored.

```json
{
  # file where the top 10 is saved
  "highscore_filename": ".highscores.json",
  "levels": [[14, 10], [15, 11], [16, 12], [17, 13], [18, 14],
             [19, 15], [20, 16], [21, 17], [22, 18], [23, 19]],
  "lives": 3,
  "pacgum": 42,
  "points_per_pacgum": 10,
  "points_per_supergum": 50,
  "points_per_ghost": 200,
  "seed": 42,
  "level_max_time": 80
}
```

| Key | Meaning | Valid values | Default |
|---|---|---|---|
| `highscore_filename` | Highscore file | any writable path | `.highscores.json` |
| `levels` | `[width, height]` of each level | width 14 to 37, height 10 to 25 | 14 × 10 up to 23 × 19 |
| `lives` | Lives at the start | 3 to 99 | 3 |
| `pacgum` | Pacgums placed in each level (capped by the free cells) | 20 to 10000 | 10000 |
| `points_per_pacgum` | Points for a pacgum | 10 to 10000 | 10 |
| `points_per_supergum` | Points for a super-pacgum | 10 to 10000 | 50 |
| `points_per_ghost` | Points for an edible ghost | 10 to 10000 | 200 |
| `seed` | Seed of level 1 (the other levels are random) | 10 to 10000 | 41 |
| `level_max_time` | Seconds for level 1 (+10 s for each next level) | 60 to 800 | 90 |

Faulty config handling (the config is modified during the defense):

- **missing or unreadable file, invalid JSON**: a clear message is printed and the
  default config is used;
- **missing key or invalid value** (wrong type, out of range): a `[VALUE ERROR]`
  message is printed and the default value of that key is used;
- **unknown keys** are ignored;
- the game never shows a traceback.

The minimum level size is 14 × 10, because the generator draws the "42" logo in the
middle of the maze and needs that much room.

## Highscore

- **Storage**: a JSON file (`{"highscores": [{"name": ..., "score": ...}, ...]}`).
  Its path comes from `highscore_filename`. When the game is packaged, it is saved
  next to the executable, so it survives between runs.
- **Loading** at game start, by `MazeLoader`. The files are tried in this order:
  the configured file, then the default `.highscores.json`, then a backup file
  `.back_up.json`. A missing file is created at the first save. A corrupted file
  (invalid JSON, wrong format) is skipped with a message.
- **Validation**: each entry is checked. The name must have 1 to 10 characters,
  letters, digits or spaces only. The score must be a non-negative integer.
  Invalid entries are ignored with a message.
- **Top 10**: the scores are sorted from best to worst and only the 10 best are kept.
- **Saving** at the end of the game: the player types a name (optional, Escape
  skips it), the score is added, the table is sorted again and the file is written
  with a context manager. Then the highscore screen opens with the player's line
  highlighted (or "not in the top 10").

Why this design: JSON is readable and easy to check by hand during the defense. The
list keeps several scores for the same name. Saving only the top 10 keeps the file
small. Loading once at start and keeping the table in memory avoids reading the
disk at every frame.

## Maze Generation

The mazes come from the given package `mazegenerator` (A-Maze-ing, version 2.1.0),
installed from the `.whl` file and **used as is**.

```python
from mazegenerator import MazeGenerator

maze = MazeGenerator((width, height), perfect=False, seed=seed)
grid = maze.maze        # list of rows: grid[y][x]
```

- `perfect=False` gives a maze **with loops**, so Pac-Man can escape the ghosts.
- Each cell is an integer where each bit is a wall: `N = 1`, `E = 2`, `S = 4`,
  `W = 8`. `cell & bit` tells whether a wall is there, and `15` is a closed cell
  (part of the "42" logo in the middle).
- Level 1 uses the `seed` of the config (always the same maze). The other levels
  use a random seed.
- If the generator fails or returns a maze of the wrong size, we retry once with
  another seed, then stop with a clear message.

From the grid, `Level` places the elements: Pac-Man in the center, the four ghosts
and the four super-pacgums in the corners, and the pacgums on random free cells.

## Implementation

**Game loop**: `App.run()` runs at a fixed 60 FPS with `time.monotonic()` and
`time.sleep()` (no `pygame.time`). Each frame it handles the events, calls
`update(dt)` on the current screen, then draws.

**Movement**: the logic works with whole cells. Each entity moves one cell every
`step_time` seconds. To make the movement smooth, the display slides the sprite
between `prev_pos` and `pos` according to `elapsed / step_time`. The rules use the
**displayed cell** (`Entity.cell`), so gums are eaten and collisions happen when
the sprites visually touch.

**Ghost AI**: the paths are computed with a breadth-first search (BFS) in the maze.

| Ghost | Class | Behaviour |
|---|---|---|
| Red | `Hunter` | Takes the shortest path to Pac-Man |
| Pink | `Tricky` | Aims up to 4 cells ahead of Pac-Man (ambush) |
| Blue | `Randomly` | Random direction, never turns back if it can avoid it |
| Orange | `Scary` | Chases Pac-Man, but goes back to its corner when it gets too close |

After a super-pacgum, the ghosts become edible for 8 seconds: they slow down and
run away. An eaten ghost goes back to its corner and comes back after 5 seconds.

**Rules**: a level is cleared when all the gums are eaten. The score and lives are
kept between levels. Losing all lives, or running out of time, ends the game
(game over). Clearing level 10 wins the game.

**Graphics (MLX rule)**: `pygame` is imported in **one file only**,
`src/graphical/renderer.py`. The `Renderer` class is a facade whose methods match
MLX functions (`new_image`, `pixel_put`, `put_image`, `string_put`, `poll_events`…).
Because MLX has no transparency, black is used as the "empty" color: the colored
pixels of a sprite are read once, then drawn one by one. The walls, the gums and the
big titles are images built pixel by pixel when a screen is created, never at
every frame.

**Errors**: every file is opened with a context manager, the errors are caught with
clear messages, and `pac-man.py` catches anything unexpected, so no traceback
reaches the player.

```
pac-man.py                 entry point: config → MazeLoader → App
src/
├── paths.py               paths of bundled files and saved files (PyInstaller)
├── logical/               game logic, never imports pygame
│   ├── parser.py          Parser: reads the JSON, removes # comments
│   ├── mazeloader.py      MazeLoader: checks the config, defaults, highscores
│   ├── game.py            Game: levels, score, lives, timer, cheats, rules
│   ├── level.py           Level: maze grid, Pac-Man, ghosts, gums
│   └── entities.py        Entity → PacMan, Ghost → Hunter, Tricky, Randomly, Scary
└── graphical/             display, reads the game state, never decides the rules
    ├── renderer.py        Renderer: the only file that imports pygame (MLX-like)
    ├── app.py             App: main loop, current screen, screen transitions
    ├── pixel_font.py      big pixel letters for the titles
    └── screens/           one class per state, all inherit from Screen
        ├── screen.py      Screen: handle_event / update / draw
        ├── menu.py        MenuScreen
        ├── game.py        GameScreen: board, sprites, HUD
        ├── pause.py       PauseScreen
        ├── end.py         EndScreen: game over / victory, name input
        ├── highscores.py  HighscoresScreen
        └── instructions.py InstructionsScreen
```

**Logic and display are separated.** The display only talks to the logic in two ways:

```python
game.handle_action(action)   # a key pressed by the player: "up", "cheat", ...
game.update(dt)              # move time forward by dt seconds
```

Everything else is read-only: the screens read `game.score`, `game.lives`,
`game.level`, `game.level_timer`, `game.result`… and draw them.

**Screens are a state machine.** `App` keeps the current screen and gives it the
events. Screens never import each other: they ask `App` to change screen
(`start_game()`, `pause()`, `end_game()`, `show_highscores()`…).

```
Menu ──Start──► Game ──Space──► Pause ──Resume──► Game
 │               │                └──Main menu──► Menu
 │               └──win / lose──► End ──Enter──► Highscores ──Escape──► Menu
 ├──Highscores──► Highscores                └──Escape──► Menu
 ├──Instructions──► Instructions
 └──Exit / Escape──► quit
```
